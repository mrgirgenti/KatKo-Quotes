Quote Builder Layout Refactor (Backend Logic Must Be Preserved)

This task is a complete UI/layout refactor of the Quote Builder. It is NOT a rewrite of the quoting engine.

The attached redesign is now the new source of truth for the Quote Builder layout.

CRITICAL

If an existing implementation conflicts with the approved design or architecture, delete and replace it. Do not preserve legacy UI for backward compatibility.

However:

Preserve existing backend logic.
Preserve existing APIs.
Preserve existing calculations.
Preserve pricing engine.
Preserve product catalog integration.
Preserve service calculators.
Preserve Client Hub submission logic.
Preserve database schema whenever possible.

The objective is to reorganize the existing functionality into the new production-first workflow, not rebuild functionality that already works.

Overall Design Philosophy

The Quote Builder should no longer feel like a long data-entry form.

Instead, every expanded Line Item should function as a complete production workspace.

When a CSR expands a line item, every piece of information required to quote and produce that design should be immediately visible without opening additional accordions or nested panels.

The only collapsible element should be the entire Line Item.

Nothing inside an expanded Line Item should require additional expansion.
