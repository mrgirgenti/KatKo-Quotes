IMPLEMENTATION MODE

Implement a comprehensive Contact Profile experience for Katalyst KO OS.

This should become the universal way to view and edit contacts throughout the application.

Reference the existing design system, architecture documentation, and UI patterns. The new Contact Profile should feel like a natural extension of the current application—not a separate experience.

If an existing implementation conflicts with the approved design or architecture, delete and replace it. Do not preserve legacy UI for backward compatibility.

DO NOT spend time researching or planning. Begin implementation immediately.

---------------------------------------
OBJECTIVE
---------------------------------------

Currently:

- Clicking a contact from within an Organization does nothing.
- Clicking a contact from the Contacts page simply opens the Organization page.
- There is no dedicated way to view or edit an individual contact.

This implementation should solve that by creating a reusable Contact Profile component.

The Contact Profile should become the standard contact experience throughout the application.

---------------------------------------
CONTACT PROFILE BEHAVIOR
---------------------------------------

Desktop:
- Clicking any contact anywhere in the application opens a right-side slide-over panel.
- The current page remains visible behind it.
- Clicking outside or Close dismisses the panel.

Mobile:
- Clicking a contact opens the exact same Contact Profile content as a full-screen page.
- Do NOT use a bottom sheet.
- Do NOT truncate the profile.
- The entire profile should be fully viewable.
- Back returns to the previous screen.

Tablet:
- Either full-screen or centered modal depending on available space.
- Maintain the same component.

The CONTENT should be identical.

Only the container changes depending on screen size.

---------------------------------------
UNIVERSAL CONTACT LINKS
---------------------------------------

Anywhere a contact name appears, clicking it should open the Contact Profile.

Examples include:

• Organizations
• Contacts
• Quotes
• Projects
• Production

• Client Hub
• Future modules

There should only be one Contact Profile component reused everywhere.
