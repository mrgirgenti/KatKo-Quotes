Prompt 10 — Complete Products + Sizes Integration (Remove Legacy Catalog Logic)

The new ConfiguredProduct architecture is now in place. The remaining issues are caused by legacy catalog logic, fallback data, and inconsistent implementations between the Internal Quote and Client Hub.

This task is not a redesign.

It is a completion and integration pass.

The goal is that both the Internal Quote and Client Hub use the exact same ConfiguredProductEditor component and the exact same data source.

Product Type

Remove the "Choose a Category" dropdown entirely.

It currently only switches between Apparel and Headwear and provides no additional value.

The clickable Product Types on the left are now the primary navigation.

Example:

T-Shirts
Polos
Crewnecks
Hoodies
Hats

Clicking one should:

highlight it
filter the Style list
update ConfiguredProduct.productType

No duplicate filtering system.

The search box should search ONLY within the currently selected Product Type.

Typing

"next"

Next Level 6210

Next Level V-Neck

etc.

If no category is selected, display all products.

Product Selection

Selecting a Style should NEVER create a "Custom Style" if that product already exists.

Currently the Client Hub displays

"No catalog matches"

after selecting an actual catalog product.

This is incorrect.

Selecting a product from the catalog must immediately bind the selected Product record to the ConfiguredProduct.

Do not fall back to custom mode unless the user manually types a style that truly does not exist.
