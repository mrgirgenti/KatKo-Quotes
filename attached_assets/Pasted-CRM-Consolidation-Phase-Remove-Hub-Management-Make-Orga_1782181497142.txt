CRM Consolidation Phase — Remove Hub Management & Make Organization Details the Single Source of Truth

STOP.

Do not audit.

Do not roadmap.

Implement.

The current Client Hub architecture is overcomplicated and still contains duplicate management systems.

We already established the intended architecture:

Organization
→ Contacts
→ Client Hub Access

Contacts are the source of truth.

Organization Details is the source of truth.

Hub Management is now redundant.

This sprint is a consolidation sprint.

⸻

OBJECTIVE

Remove Hub Management as a people-management surface.

Move all remaining useful functionality into Organization Details.

Create one authoritative place to manage:

* Contacts
* Hub Access
* Org Admins
* Hub Sharing
* Hub Status
* Hub Readiness

No duplicate interfaces.

No duplicate datasets.

No duplicate workflows.

⸻

SOURCE OF TRUTH RULE

The CRM is the source of truth.

Specifically:

Organization
→ Contacts

Everything derives from Contacts.

Not:

* Memberships
* Hub Users
* Team Members
* Hub Management datasets

Those are implementation details.

The UI should never present them as separate systems.

⸻

REMOVE HUB MANAGEMENT AS A MANAGEMENT SURFACE

The following should no longer be editable from Hub Management:

* Team Members
* Org Admins
* Invite Contact
* Member Roles
* Hub User Management

These functions belong to Contacts.

If Hub Management remains temporarily:

It becomes a read-only operational dashboard.

No people management.

⸻

ORGANIZATION DETAILS ENHANCEMENTS

The Client Hub section inside Organization Details becomes the home for Hub administration.

Move or surface:

* Hub On / Off
* Hub URL
* Copy URL
* Open Hub
* QR Code
* Hub Readiness
* Hub Metrics

directly within Organization Details.

The user should not need to leave the Organization Details page to manage a Client Hub.

⸻

CONTACT MANAGEMENT RULES

Contacts are the only place where:

* Hub Access is granted
* Hub Access is revoked
* Org Admin is assigned
* Org Admin is removed

There should never be another interface that manages those permissions.

METRIC RULES

Hub Users

= Contacts with Hub Access

Org Admins

= Contacts with Org Admin enabled

Pending Invites

= Contacts invited but not activated

No separate membership counts.

No separate team-member counts.

READINESS RULES

Readiness derives from:

* Hub Enabled
* Contact Exists
* Hub User Exists
* Org Admin Assigned
* Logo Uploaded

Everything should use CRM data.

No duplicate calculations.
