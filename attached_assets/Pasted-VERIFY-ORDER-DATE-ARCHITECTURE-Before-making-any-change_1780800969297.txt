VERIFY ORDER DATE ARCHITECTURE

Before making any changes, perform a full audit of how Order Date is currently handled throughout the platform.

DO NOT implement anything yet.

Provide a verification report first.

==================================================
OBJECTIVE
=========

We need to determine whether Order Date is already functioning correctly throughout the CRM/ERP.

Order Date is critical because:

* Active Projects are processed FIFO
* Submitted Quotes are processed FIFO
* Production Queue will be processed FIFO
* Queue numbering depends on Order Date
* Reporting depends on Order Date

Before we make changes, confirm what currently exists.

==================================================
VERIFY DATABASE
===============

Inspect all relevant models.

Determine:

1. Does Quote have an Order Date field?
2. Does Project have an Order Date field?
3. Is Order Date nullable?
4. Is Order Date required?
5. What is the field name exactly?
6. Does the database provide a default value?
7. Does Prisma provide a default value?
8. Are any records currently missing Order Dates?

Provide findings.

==================================================
VERIFY QUOTE CREATION
=====================

Inspect every quote creation path.

Determine:

1. When a quote is created, is Order Date automatically populated?
2. If populated, where does the value come from?
3. Does it use:

   * current date
   * createdAt
   * user input
   * another source
4. What happens if the user leaves Order Date blank?
5. Can a quote be saved without Order Date?

Provide exact code locations.

==================================================
VERIFY PROJECT CONVERSION

Determine:

3. Is it overwritten?
4. Is a new Order Date generated?
5. Can Project Order Date differ from Quote Order Date?

Provide exact code locations.
