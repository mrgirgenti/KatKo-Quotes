====================================================
OBJECTIVE
====================================================

Protect apparel size upcharges from drifting when serviceStyle changes.

The pricing engine currently applies apparel size upcharges (2XL/3XL/4XL/etc.) through:

computeSizeUpcharge()

When serviceStyle changes between garment-based styles and flat-quantity styles, the size upcharge calculations must continue to produce correct totals.

====================================================
TEST COVERAGE
====================================================

Add regression tests covering:

----------------------------------------------------
Scenario 1

Screen Printing

↓

Garment quantities

↓

2XL / 3XL garments

↓

Switch to Promotional

----------------------------------------------------

Verify:

• Promotional (flat quantity) does NOT continue applying garment size upcharges.

• Product total is recalculated correctly.

• No stale upcharges remain.

----------------------------------------------------
Scenario 2

Promotional

↓

Flat quantity

↓

Switch to Screen Printing

↓

Garment quantities include 2XL / 3XL

----------------------------------------------------

Verify:

• Size upcharges become active again.

• Only qualifying garment quantities receive upcharges.

• Standard sizes remain unaffected.

----------------------------------------------------
Scenario 3

Multiple Products

Multiple Sizes

Service Style Switch

----------------------------------------------------

Verify:

• Blended product cost remains correct.

• Size upcharges remain correct.

• Total quantity remains correct.

• Production Cost remains cent-exact.

ASSERTIONS
