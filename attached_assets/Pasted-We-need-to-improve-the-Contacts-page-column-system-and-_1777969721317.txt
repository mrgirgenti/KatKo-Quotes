We need to improve the Contacts page column system and phone number formatting.

======================================================================
1. CONTACTS PAGE COLUMN VIEW
======================================================================

Current Contacts page is too rigid. I want the ability to adjust/customize the column view so I can show the information I actually need.

Please add a column view/settings control for the Contacts table.

The columns I regularly want visible are:

1. Organization
2. Business Type
3. Primary Contact
4. Primary Contact Phone Number
5. Primary Contact Email Address
6. Status
7. Client Hub
8. Actions

These should be available as selectable columns in the column settings.

Default visible columns should be:
- Organization
- Business Type
- Primary Contact
- Primary Contact Phone Number
- Primary Contact Email Address
- Status
- Client Hub
- Actions

======================================================================
2. COLUMN FILTERING
======================================================================

Each column should always be filterable.

Please add/filter support for:
- Organization
- Business Type
- Primary Contact
- Phone Number
- Email Address
- Status
- Client Hub status

Filtering should be clean and usable, not cluttered.

Use appropriate filter types:
- text search for Organization, Contact, Phone, Email
- dropdown/multi-select for Business Type
- dropdown/multi-select for Status
- dropdown/multi-select for Client Hub Active/Inactive

Sorting should continue to work where applicable.

======================================================================
3. PRIMARY CONTACT DISPLAY
======================================================================

The Contacts table should clearly display the primary contact’s:

- name
- phone number
- email address

These should be separated into their own columns, not crammed into one stacked cell.

If there is no primary contact:
- show “No primary contact”
- keep formatting clean and muted

======================================================================
4. PHONE NUMBER NORMALIZATION
======================================================================

No matter how a phone number is entered, the system should automatically normalize and display it in this format:

(###) ###-####

Examples:

Input:
- 6236925062
- 623.692.5062
- (623) 692-5062
- 623-692-5062
- 623 692 5062

Output:
- (623) 692-5062

This should apply to:
- contact creation
- contact editing
- organization/contact display
- Contacts table
- Client/Organization profile page
- any phone number field shown in the OS or Client Hub where appropriate

======================================================================
5. PHONE NUMBER STORAGE / VALIDATION
======================================================================

Please implement phone formatting carefully.

Recommended approach:
- strip non-numeric characters on input
- validate that U.S. phone numbers contain 10 digits
- store normalized value consistently
- display as (###) ###-####

If a number is invalid:
- show a clear validation message
- do not silently save a malformed number

If we later need international numbers, we can expand the logic later. For now, prioritize clean U.S. phone number formatting.

======================================================================
6. RESPONSIVE BEHAVIOR
======================================================================

Because the Contacts table will have more columns, make sure tablet/mobile behavior still works.

Requirements:
- desktop: show full selected columns where possible
- tablet/mobile: allow horizontal scroll or convert to card layout
- Actions must remain accessible
- text should not become unreadably small
- columns should not crush each other

======================================================================
7. FINAL GOAL
======================================================================

Contacts should become a flexible, useful management table.

I should be able to quickly see:
- organization
- business type
- primary contact
- phone
- email
- status
- client hub status
- actions

Phone numbers should always look clean and professional, regardless of how they were typed in.
