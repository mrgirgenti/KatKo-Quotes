Products UX Refactor — Workflow Alignment

Context

The underlying catalog architecture is becoming solid.

The current issue is workflow and information architecture.

The Products section should become the primary workspace for managing products.

Avoid creating additional management pages unless they solve a truly separate workflow.

The goal is to align the system with how a real apparel decorator, CSR, sales rep, production manager, or shop owner actually manages products.

Core Principle

Products should be managed from the Products table.

Product Detail should only contain information unique to a specific product.

Administrative utilities should live in a dropdown menu.

Do not create additional standalone management pages unless absolutely necessary.

2. Rename "Catalog" Dropdown

Current:

Catalog ▼

Change to:

Actions ▼

Reasoning:

The dropdown contains actions and utilities.

Examples:

Actions ▼
├─ Product Audit
├─ Vendors (future)
├─ Import CSV
├─ Export CSV
├─ Auto Resolve Templates

"Catalog" is misleading.

"Actions" more accurately reflects its purpose.

──────────────────────────────────────

3. Remove Dedicated Manage Costs Page

The current Manage Costs page should be removed.

Cost management belongs directly in the Products table.

Implement:

Inline cost editing.

Behavior:

* Click Cost cell
* Cell becomes editable
* Enter or blur saves
* Multiple rows can be edited independently
* Saving indicator
* Saved confirmation
* Missing costs remain visually obvious

Products should not require navigation to a separate page to edit costs.

CSV imports remain available through Actions.

──────────────────────────────────────

4. Bulk Cost Editing

Add cost management to Bulk Actions.

Examples:

Select products

Bulk Actions
├─ Set Cost
├─ Increase Cost %
├─ Decrease Cost %
├─ Clear Cost

Use cases:

Vendor price increases
Seasonal adjustments
Catalog cleanup

This is significantly more valuable than a dedicated cost management page.

──────────────────────────────────────

5. Product Detail Simplification

Product Detail should only contain product-specific information.

Keep:

* Colors
* Assets
* Placements
* Sources

Do not add:

* Cost management
* Audit tools
* Catalog utilities

Those belong elsewhere.

The Sources tab remains because:

Vendor SKU
Vendor URL
Preferred Vendor
Vendor Notes

are legitimately product-specific.

8. Product Audit

Audit is the correct place.
