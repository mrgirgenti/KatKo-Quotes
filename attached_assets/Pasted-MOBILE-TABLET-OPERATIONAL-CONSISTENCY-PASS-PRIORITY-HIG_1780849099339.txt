MOBILE & TABLET OPERATIONAL CONSISTENCY PASS

PRIORITY: HIGH

This is NOT a styling request.

This is NOT a responsive rendering request.

This is an operational workflow request.

Desktop, tablet, and mobile must support the same workflow and mental model.

==================================================
PROBLEM

The desktop versions of Projects and Quotes have evolved into a column-driven operational system.

Desktop users can immediately understand:

Status

Order Date

Due Date

Client

Project

Quote #

Service

PCS

Revenue

Profit

because those fields are explicitly labeled and sortable.

On mobile and tablet, those same records have been converted into generic cards.

The data still exists, but the column context has been lost.

Users can no longer immediately identify:

Is this Order Date or Due Date?

Is this the Client or Project?

Is this a Service or Applicator?

Which fields correspond to sortable desktop columns?

This creates a completely different operational experience.

==================================================
REQUIREMENT

Mobile and tablet should preserve the meaning of desktop columns.

Users should not have to remember what each value represents.

Every sortable/filterable desktop field should remain identifiable on mobile.

==================================================
DO NOT

Do not simply make prettier cards.

Do not optimize for aesthetics over operations.

Do not hide important field labels.

Do not create a separate mobile workflow.

==================================================
GOAL

A production employee using a phone or tablet should process jobs using the exact same information hierarchy as a desktop user.

The layout can change.

The workflow cannot.
